# Locale

On Route includes built-in multi-language support. The active language is detected automatically from the browser, with an English fallback. Users can change their language in the Settings panel.

---

## Language resolution

The active language is resolved in this order:

1. **Stored user preference** — a language the user selected in the Settings panel, saved to `localStorage`
2. **`?locale=` URL param** — set on the iframe `src` to control the initial locale
3. **Browser language** — `navigator.language`, matched against available languages; if the exact region code (e.g. `fr-CA`) is not available, the base code (`fr`) is tried
4. **English fallback** — `'en'` is used if no other match is found

---

## URL param

The `?locale=` URL param sets the default language when the user has no stored preference:

```html
<iframe src="/app/?locale=fr"></iframe>
```

## Available languages

| Code | Language |
|------|----------|
| `en` | English  |
| `fr` | Français |

## Persistence

The user's language selection is stored in `localStorage` as part of the settings object:

```js
useStorage("settings", { theme: null, units: null, language: null });
```

Storage key: `onrte_settings_{instanceId}`

`language: null` means "follow the browser or URL param". Once the user selects a language, an explicit code is written and used on every subsequent load.

## Composable API — `useLocale()`

```js
import { useLocale } from "@/composables/useLocale.js";

const {
  locale,         // Ref<string>             — active language code, e.g. 'en', 'fr'
  locales,        // string[]                — all available language codes
  localeNames,    // Record<string, string>  — native display names
  mapLanguageTag, // Ref<string>             — locale code for OSM name:xx lookups
  t,              // (key: string) => string — translate a key; falls back to English
  setLocale,      // (code: string) => void  — change the active language
} = useLocale();
```

`t(key)` is reactive — template expressions re-evaluate when the locale changes. Missing keys fall back to English; if also missing from English, the key itself is returned.

---

## Translation keys

Keys use dot-separated namespaces that mirror the UI structure:

| Namespace | Example key | English value |
|-----------|-------------|---------------|
| `nav.*` | `nav.menu` | Menu |
| `menu.*` | `menu.shareThisView` | Share this view |
| `modal.welcome.*` | `modal.welcome.title` | About On Route |
| `settings.*` | `settings.darkMode` | Dark mode |
| `locate.*` | `locate.button.locate` | Locate |

Full list: [`src/locales/en.json`](../src/locales/en.json), [`src/locales/fr.json`](../src/locales/fr.json).

---

## Contributing a translation

1. Copy `src/locales/en.json` to `src/locales/{code}.json`
2. Translate the values — partial translations are safe; untranslated keys fall back to English
3. Add the code to `LOCALES` and its native name to `LOCALE_NAMES` in `src/composables/useLocale.js`

For script-variant languages always use the full BCP 47 subtag: `zh-Hans`, `zh-Hant`, `sr-Latn`, etc.

## OSM multilingual names

On Route locale codes align with the [OSM multilingual names convention](https://wiki.openstreetmap.org/wiki/Multilingual_names). Every locale code is a valid OSM `name:xx` tag suffix — no conversion needed.

Map labels update automatically when the user changes language. On `style.load`, `useMap` applies the following coalesce expression to every symbol layer:

```js
["coalesce",
  ["get", "name:fr"],  // preferred language
  ["get", "name"],     // local / native name
  ["get", "name:en"],  // English fallback
]
```

The expression is re-applied reactively whenever `mapLanguageTag` changes.

```js
const { mapLanguageTag } = useLocale();
// mapLanguageTag.value === 'fr' when French is active
```
