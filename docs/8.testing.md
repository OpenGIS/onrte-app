# Testing

On Route has two test layers:

- **Unit tests** (Vitest) — test pure composable logic in milliseconds
- **E2E tests** (Playwright) — test full browser integration

```bash
npm run test:unit                                     # Vitest — <1 s
npm run test:e2e -- tests/e2e/core.spec.js            # single spec (15–45 s)
npm run test:e2e                                      # full E2E suite (2–3 min)
npm test                                              # unit tests only (final check)
```

---

## Unit tests

Unit tests live in `tests/unit/` and cover pure, extractable logic from composables:

| Test file | Composable | What it tests |
|-----------|------------|---------------|
| `tests/unit/EventEmitter.test.js` | `EventEmitter.js` | on/off/once/emit |
| `tests/unit/useStorage.test.js` | `useStorage.js` | Storage key format, localStorage, instance isolation |
| `tests/unit/useUrlHash.test.js` | `useUrlHash.js` | URL hash parsing and formatting |
| `tests/unit/useLocale.test.js` | `useLocale.js` | Locale resolution, `t()`, mapLanguageTag |
| `tests/unit/useSettings.test.js` | `useSettings.js` | `localeDefaultUnits()` mapping |
| `tests/unit/useUI.test.js` | `useUI.js` | Breakpoints, panel/nav state, about modal |
| `tests/unit/useGeoJSON.test.js` | `useGeoJSON.js` | Feature CRUD, style defaults, colour assignment |

When adding new composable logic, consider whether it can be tested as a pure function. If so, add a unit test in `tests/unit/`.

## Running a specific E2E spec

```bash
npm run test:e2e -- tests/e2e/core.spec.js
npm run test:e2e -- tests/e2e/core.spec.js --grep "About panel"
```

## E2E structure

E2E specs live in `tests/e2e/` and test behaviour in the real browser:

```
tests/
  unit/                    ← Vitest unit tests
  e2e/
    core.spec.js           ← core UI: first load, about, privacy
    features/
      locate.spec.js       ← GPS locate
      recordings.spec.js   ← recordings feature
      settings.spec.js     ← user preferences
    screenshots/
      readme.spec.js       ← assets/screenshots/app-preview.png
```

## Writing E2E tests

```js
import { test, expect } from "@playwright/test";

test.describe("My feature / My heading", () => {
  test("does the thing", async ({ page }) => {
    await page.goto("/");
    await expect(page.locator(".my-element")).toBeVisible();
  });
});
```

- Use `page.addInitScript` to seed `localStorage` before navigation
- Storage keys: `onrte_{namespace}_{instanceId}` — the default id is `'app'`, so the view key is `onrte_view_app`
- Poll for throttled async side-effects with `expect.poll()` rather than `waitForTimeout`

## Screenshots

Screenshots are captured by Playwright and live in `assets/screenshots/`. To regenerate:

```bash
npm run test:e2e -- tests/e2e/screenshots/readme.spec.js
```

Screenshots are committed to the repository so docs render correctly on GitHub.

**Conventions:**
- Full viewport at **1280×720** (desktop) unless illustrating a specific breakpoint
- Test names describe the UI state being captured
- Add a screenshot when the visual output meaningfully illustrates the behaviour
